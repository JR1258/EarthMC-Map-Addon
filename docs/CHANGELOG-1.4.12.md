# 1.4.12

**Search**
- The search bar remembers what you open. The hint rows above it -- the filter and archive tips -- are now the top of a list that scrolls, with your last ten searches underneath them, newest first and nearest the bar. Roll the wheel down over the rows to go further back, drag the scrollbar that appears down their right-hand side, or press the down arrow from an empty bar and Enter to reopen one. Each row carries the same one-letter tag the favourites list uses, and how long ago you looked.
- A remembered search takes you to wherever that town, nation or player is now, not to where it was when you searched it: a town that has claimed or unclaimed since still leads to the right place. One that has been deleted is greyed out rather than quietly dropped, so the list never looks as though it is losing entries by itself. The Info Panel's search box feeds the same list, so both boxes remember together.
- Only what you actually open is kept, never what you type, and only when you search: following a link from one page to the next is browsing and leaves the list alone. Nothing is recorded while you are looking at an archived snapshot, so visiting a date cannot leave you with rows that lead nowhere. "Search History" in the settings stops the recording and "Clear Search History" empties the list; with it off the bar shows the three hint rows exactly as before.

**Performance**
- The minimap no longer asks the server who is still online once for every player it remembers. That lookup walks the whole tab list, and on EarthMC that list runs to hundreds, so it was the most expensive thing the minimap did each time it refreshed its last-seen markers. It now reads the list once.
- Starred towns are checked without building a lowercase copy of every town's name on every frame, and with no favourites at all the check does nothing. The "nearest town" line compares squared distances across the whole town list and takes one square root at the end instead of nearly six thousand.
- Xaero's minimap shape and arrow scale are read through settings the addon now looks up once per session rather than re-resolving ten times a second, which had been copying that class's entire method list each time.
- Fixed a second runaway, in the alliance and meganation data. The five-minute wait between refreshes only applied once a refresh had succeeded, so a failed one left no wait at all: the next frame tried again, and the next. A log from one session caught 209 requests in 18 seconds, which is fast enough to be what got the addon refused in the first place -- after which every reply was a refusal and the loop fed itself. The wait now applies either way and lengthens while the source stays down. A refresh that starts being refused partway through its list also stops, instead of asking for every remaining alliance and being turned down for each.
- Cached player details no longer accumulate for a whole session. Entries went out of date after ten minutes and were fetched again, but the old one was never removed, so a long session browsing the map kept a copy of every player it had ever looked at.
- The saved town-detail cache drops towns that are no longer on the map. Nothing ever removed an entry, so it kept every town ever looked at, loaded the lot back at launch and held it for the session. On a long-running install it had reached about seven thousand entries against fewer than six thousand live towns.

**Nations**
- A town's nation is no longer given as "Capital of <nation>" in places that wanted the nation's name. The map's tooltips word a capital's nation that way and the addon stored it exactly as it arrived, so for every nation that has a capital: the card and the Expand page for a player the API has nothing for read "Nation: Capital of Switzerland", the label under their dot on the map read "Bern / Capital of Switzerland", and the nation link on that card led nowhere. The capital is still said in words where it belongs, on the town hover and the right-click title, and the card now says it the way the rest of the mod does -- "Capital of:" as the label, with the nation's own name beside it.
- The Stats nation tables counted every nation with a capital twice. "Switzerland" and "Capital of Switzerland" were two different rows, so that nation's towns, residents and chunks were split between them and the nation total came out too high.
- Players living in your nation's capital are coloured as nation-mates again. The same mismatch meant a capital's resident never compared equal to anyone else in the nation, so they were drawn as strangers unless you lived in the capital yourself.

**Other servers**
- The world map is no longer black on a server the addon has nothing to do with. With "EarthMC Only" on, which is the default, nothing of the addon is drawn on another server and it says so in the log -- but it was still pointing Xaero's world map at whatever world it had worked out, every time the map was opened. On a server with more than one world that is the overworld, which on a build or creative server is usually the hub, so Xaero was moved off the world it had spent the session mapping and onto an empty one. It now leaves Xaero's map alone on any server it is idle on.
- The addon also no longer moves Xaero's map to a world it only guessed at. It recognises the worlds the map publishes by name; anything else was being treated as the overworld, which is right for the Nether and the End but also catches every extra world a server adds, since those are named the same way. When the world cannot be recognised, Xaero keeps showing the dimension you are standing in, and its own dimension button and the Earth/Moon setting still override that. The log now names the world when this happens.

**Fixes**
- Fixed a runaway that could fill Minecraft's memory. While the mod was waiting for your own EarthMC record, it asked for that record again on every single frame instead of once. Usually the answer came back within a few frames and nothing showed; when it was slow, the flood of requests tripped EarthMC's rate limit, every answer after that failed, so the record never arrived and the requests never stopped. A memory snapshot taken during one of these caught 3.2 million queued lookups filling a 5 GB heap to 100%, which is enough to stutter or crash the game. The lookup now goes out once and waits before trying again if it fails, and the blocklist check that set it off no longer re-runs every frame.
- In the Nether or the End, Xaero's map shows the Nether or the End. It was being moved to the overworld, so with the overlay hidden out there, which is the default, the map showed overworld ground you were not standing on. In "Overworld Coords" mode the EarthMC overlay now has the real Nether tiles underneath it to line up with, which is what that mode was for.

Available for Minecraft **1.21.11**, **26.1.x**, **26.2** and **26.3**.
